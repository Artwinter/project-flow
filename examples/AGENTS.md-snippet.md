# 建议加到 AGENTS.md / CLAUDE.md 的片段

技能靠描述匹配触发，会受措辞波动影响。`AGENTS.md` 是每轮强制注入的，
命中率 100%。四行换确定性，值得。

---

## 片段（直接复制）

```markdown
## 新项目 / 新想法 → 先走立项流程

当我说"我想做个 X""我有个想法""开坑""立项"，或开始一个全新项目 / 全新功能、
且需求还模糊时：**先调用 `project-flow` 技能给出路由，不要直接写代码**。
```

---

## 为什么是这四行

| 元素 | 作用 |
|---|---|
| 触发短语 | 覆盖中文口语，不依赖技能描述匹配 |
| "或开始一个全新项目/新功能" | 兜住没说触发词但明显是新活的情况 |
| "且需求还模糊" | 避免把"想清楚了的小改动"也拖进流程 |
| "不要直接写代码" | 最关键的一句——这是要拦的行为 |

---

## 放在哪里

- 全局：`~/.claude/CLAUDE.md` 或 `~/.dsh/AGENTS.md`
- 单项目：项目根 `AGENTS.md` / `CLAUDE.md`

**建议放全局**。新项目开始时，项目根往往还不存在。

**具体位置**：放进「开工判定」那一节里，接在该节已有条目之后。理由——
它本质上就是一条开工判定规则（"这种活儿先走流程，不要直接动手"），
放进独立章节反而会被当成补充说明跳过。

---

## 如果你的 agent 支持自定义命令

可以再加一个短口令，例如 `/kickoff`，正文就一句：

```
调用 project-flow 技能，进入立项流程。
```

这样"开坑"和 `/kickoff` 双通道，一个自然语言、一个确定性。
